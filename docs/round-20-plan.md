# R20 主指标口径贯通三处（主卡片 / 托盘浮层 / 右键菜单）— 执行规格

## 0. 问题与基准

- 用户原话：「eto 这种的你改了主界面，但没有改状态栏托盘卡片和右键菜单」。
- **右键菜单** `tray.rs#tray_status_text()`：优先级「失败 → **余额** → **已用**百分比最高的窗口 →「—」」→ 余额 0 的订阅账号显示 `$0.00`，且百分比是**已用**口径（与主界面语义相反）。
- **悬停浮层** `summaryData.ts:141-142`：`balanceText(balance) ?? pct%` → 同样「余额 0 也算主指标」，且 `tightestQuotaPercent` 为**已用**口径。
- **口径基准（R19 已落地，不改）**：`src/primaryMetric.ts#pickPrimaryMetric` —— 有效窗口 ≥1 且（余额 null 或 0）→ 订阅**剩余**（最紧窗口 = usedPercent 最大者；剩余 = 100 − clamp(used,0,100)，最多 2 位、去尾 0）+ 窗口名；否则余额；余额 null 且无有效窗口 →「—」。
- **本轮输入**：现有数据（`AccountInfo.balance` / `quota_windows` / 失败 reason），**不改任何数据口径**；只改「显示口径与字符串」。

## 1. 统一输出口径（三处共用同一组「语义 + 字符串」）

**单行规范串**（托盘菜单与浮层**逐字一致**）：

| 状态 | 规范串 | 说明 |
|---|---|---|
| 失败（`ok=false`） | `✗ {原因}` | 优先级最高；原因用**12 字符**截断规则（取 11 字符 + `…`），与托盘现状一致 |
| 订阅优先 | `剩余 {剩余}%（{窗口名}）` | `剩余` = `100 − clamp(已用,0,100)`，**最多 2 位小数、去尾 0**（100 → `100`、73.14 → `73.14`）；窗口名缺失/空白 → `当前窗口` |
| 余额优先 | `{金额} {币种}` | 金额小数位＝现有 `format_decimal` 规则（`|v|≥1`→2 位、`0.01≤|v|<1`→4 位、`0<|v|<0.01`→6 位、**0→`0.00`**）；例：`12.50 USD`、`0.00 USD`、`0.5000 USD` |
| 无数据（`info` 为 null，或余额 null 且无有效窗口） | `—` | — |

- **判定顺序完全等于 `pickPrimaryMetric`**：失败（结果层，独立于 info）→ 订阅优先 → 余额 → 无数据；`usedPercent` 为 `null`/`NaN` 一律**忽略该窗口**，全忽略则回落余额分支；越界钳制 `<0→100%`、`>100→0%`。
- **主卡片（R19，不改排版）**：订阅分支仍显示「订阅剩余 {剩余}%」大字 + 窗口名 + 倒计时；**其 `剩余`/窗口名 token 必须与单行规范串中的同名 token 逐字相等**。余额分支保持 R19 排版（`$12.50` 大字 + 币种），**不纳入字符串级 AC**（仅口径一致）。
- **明确的语义修正（有意变更，需写进 review）**：托盘菜单原显示**已用**百分比（如 Kimi「5h 27%」），本轮统一改为**剩余**（`剩余 73.14%（5h）`）—— 这是用户「百分比余量」要求的直接后果，**Kimi 在托盘上的显示会变**。

## 2. 单一事实来源策略

- **前端浮层**：**必须复用** `src/primaryMetric.ts#pickPrimaryMetric`（禁止第二份判定逻辑）；`summaryData.ts` 的 `valueText` 改为「规范串生成函数」的输出，失败态用结果层的 `✗ 原因`（12 字符）。新增 `formatPrimaryMetricLine(metric): string`（同文件或 `src/primaryMetricLine.ts`）作为唯一出口。
- **Rust 侧**：新增 `src-tauri/src/primary_metric.rs`（等价纯函数）：`pick_primary_metric(&AccountInfo) -> PrimaryMetric` + `format_primary_metric_line(...) -> String`；`tray_status_text()` 改为「失败分支（保持）→ 调该函数」的薄封装。**不得**在 `tray.rs` 里再抄一份判定。
- **防漂移（本轮核心）**：§3 黄金表为**唯一主表**；Rust 与 TS 各自把该表**逐字**嵌成测试常量并断言输出相等。终审会机械 diff「两侧嵌入表 ↔ 本表」，任一侧漂移即红灯。

## 4. AC 清单

- **AC-1** 规范串格式（§1）：四种状态的字符串形态与上表逐字一致。
- **AC-2** 订阅优先（§1/§3）：G1、G2 通过（剩余 100 / 73.14、取最紧窗口、窗口名携带）。
- **AC-3** 余额优先（§1/§3）：G3、G4、G12 通过（含 0 → `0.00 USD`、0.5 → `0.5000 USD`）。
- **AC-4** 降级与无数据（§1/§3）：G5、G6、G7、G11 通过（null/NaN 窗口忽略、余额 null 且无窗口 →「—」）。
- **AC-5** 窗口名与越界（§1/§3）：G7、G8、G9 通过（空白窗口名 →「当前窗口」；越界钳制）。
- **AC-6** 失败态（§1/§3）：G10 通过（`✗` + 12 字符截断，优先级高于余额/窗口）。
- **AC-7（跨语言一致性，本轮核心）**：同一黄金表在 **Rust 与 TS 两侧**断言输出字符串**逐字相同**；且两侧嵌入的表与本规格 §3 **逐字一致**（终审机械 diff 两侧常量与 §3）。
- **AC-8** 三处口径贯通（§1/§2）：订阅账号下，主卡片 `剩余`/窗口名 token 与规范串同名 token 相等；托盘与浮层字符串**完全相等**。
- **AC-9** 语义修正生效（§1）：Kimi 托盘由「已用 %」变为 `剩余 73.14%（5h）`（若 G2 值随真实数据变化，以「剩余」口径为准）；相关旧断言按新口径更新且**逐条列出**。
- **AC-10** 无回归：主卡片 R19 行为与排版不变（除本口径要求的 token 一致性）；浮层布局/样式/交互（Escape、指针回报、行点击）不变；R14–R19 的数据口径断言删除/改动 = 0；既有前端 399 与 Rust 90 用例只增不减；`tsc`/`npm test`（本机+UTC）/`cargo test`/`clippy`/`fmt`/`vite build`（入口无 recharts）全绿。

## 5. 自查与不做

**AC→§**：AC-1..AC-6→§1/§3；AC-7→§2/§3；AC-8→§1/§2；AC-9→§1；AC-10→§0/§1。**笔算**：G1 `100−0=100`；G2 `100−26.86=73.14`；G7 `100−20=80`；G8 `clamp(−5)=0→100`；G9 `clamp(150)=100→0`；G10 原因前 11 字 =「连接超时：无法访问上游」+`…`；G12 `0.5` 落 `0.01≤|v|<1` → 4 位 → `0.5000` ✔
**不做**：不改数据口径/解析；不改主卡片 R19 的排版与判定；不加依赖；不动托盘交互（左键切换/右键菜单结构/tooltip）与浮层布局样式；不处理非启用账号（口径外）；不做本地化/单位换算。
**本轮有意变更（review 需逐条记录）**：① 托盘「已用 %」→「剩余 %」；② 浮层余额格式 `$12.50` → `12.50 USD`（单行统一）；③ 浮层失败原因截断 24 → **12** 字符（与托盘一致，只影响显示长度、不丢语义）。
