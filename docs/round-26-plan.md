# Round 26：悬停保活坐标修正与缩放边缘保活

## 1. 用户反馈

v0.2.8 没有解决从托盘图标移向浮层时的消失问题。光标进入浮层后可以保持显示，但移向边缘准备缩放时，浮层仍会消失。因此用户难以开始原生缩放。

## 2. 根因

### 2.1 光标坐标重复叠加窗口原点

当前锁定的 Tauri 版本是 2.12.2。其 `WebviewWindow::cursor_position()` 返回桌面绝对物理坐标。Tao 0.37.1 在 Windows 上直接调用 `GetCursorPos`。

v0.2.8 错把该值当成窗口相对坐标，又叠加了一次 `outer_position()`。浮层位于屏幕右下方时，计算结果会偏到浮层右下方。隐藏前的驻留判定因此经常失败。

### 2.2 保活余量未覆盖缩放边缘

v0.2.8 只向浮层外扩 6 物理像素。Tao 在 Windows 上按 DPI 读取 `SM_CXFRAME` 和 `SM_CYFRAME`，用它们计算原生缩放边缘。高 DPI 下，6 物理像素不能可靠覆盖该区域。

光标进入边缘后，前端可能收到离开事件并启动隐藏计时器。原有余量不足时，浮层会在用户开始缩放前隐藏。

### 2.3 WebView 内部失焦会绕过驻留判定

前端原来监听 `window.blur` 并立即隐藏浮层。原生缩放可能让 WebView 内部失焦，但顶层浮层仍然有效。这条路径不会执行光标驻留判定，所以可能中断缩放。

## 3. 修复

1. `cursor_screen_position` 直接使用 `cursor_position()` 返回的桌面坐标，不再叠加窗口位置，也不除以缩放因子。
2. `KEEPALIVE_MARGIN_PX` 从 6 调整为 24。该余量同时覆盖图标到浮层的间隔、透明边距和高 DPI 缩放边缘。
3. 保留现有原生缩放入口。隐藏计时器仍每 200 毫秒读取最新光标和窗口几何。缩放改变窗口尺寸后，判定使用新的 `outer_size()`。
4. 删除前端的 WebView `blur` 直接隐藏处理。顶层窗口失焦仍由 Rust 的 `Focused(false)` 处理，真实切换窗口的行为不变。
5. 新增回归用例，覆盖窗外 16 物理像素的缩放边缘和超出 24 物理像素后的隐藏行为。前端用例同时确认 WebView 内部失焦不会直接隐藏浮层。

## 4. 验证

- 前端 489 条测试通过。
- TypeScript 检查和 Vite 生产构建通过。
- `cargo fmt --check` 通过。
- 本机缺少 MSVC `link.exe`，所以 Rust 编译和单元测试由 CI 执行。
- 原生托盘交互无法由 jsdom 覆盖。发布后需要在 Windows 上实测缓慢移入浮层、进入边缘和拖拽缩放。
