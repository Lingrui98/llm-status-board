# Round 26：悬停保活坐标修正与缩放边缘保活

## 1. 用户反馈

v0.2.8 没有解决从托盘图标移向浮层时的消失问题。光标进入浮层后可以保持显示，但移向边缘准备缩放时，浮层仍会消失。因此用户难以开始原生缩放。

## 2. 根因

### 2.1 光标坐标重复叠加窗口原点

当前锁定的 Tauri 版本是 2.12.2。其 `WebviewWindow::cursor_position()` 返回桌面绝对物理坐标。Tao 0.37.1 在 Windows 上直接调用 `GetCursorPos`。

v0.2.8 错把该值当成窗口相对坐标，又叠加了一次 `outer_position()`。浮层位于屏幕右下方时，计算结果会偏到浮层右下方。隐藏前的驻留判定因此经常失败。

### 2.2 原生缩放边框改变鼠标事件目标

Tauri 在 Windows 上为无边框窗口创建原生缩放边框。该边框位于窗口外接矩形内侧，不是浮层外的区域。光标进入边框后，WebView 会收到离开事件，隐藏计时器随后启动。v0.2.8 的错误坐标会让驻留判定再次失败。

右下角手柄原来距离窗口边缘只有 2 像素。它的一部分与原生缩放边框重叠，所以手柄不一定能收到鼠标按下事件。

### 2.3 WebView 内部失焦会绕过驻留判定

Tauri 在 Windows 上会把 WebView 的 `LostFocus` 合成为 Rust 的 `Focused(false)`。原生前端 `window.blur` 和 Rust `on_popup_blur` 都会立即隐藏浮层。两条路径都绕过光标驻留判定，可能中断原生缩放。

## 3. 修复

1. `cursor_screen_position` 直接使用 `cursor_position()` 返回的桌面坐标，不再叠加窗口位置，也不除以缩放因子。
2. 保留 6 物理像素的既有外扩余量。原生缩放边框已经位于 `outer_position()` 和 `outer_size()` 组成的外接矩形内，不需要扩大普通移出时的保活范围。
3. Windows 的 `on_popup_blur` 同步比较系统前台窗口与浮层句柄。浮层仍是前台窗口时忽略内部失焦，真实切窗时隐藏。该方式不使用 WebView 的焦点缓存，也不引入延时任务竞态。其他平台直接读取 Tauri 顶层焦点。读取失败时统一隐藏，避免浮层无法关闭。
4. 删除前端的 WebView `blur` 直接隐藏处理。真实失焦统一由 Rust 复核后处理。
5. 右下角手柄调整为 20×20 像素，并内移到距边缘 10 像素的位置。手柄由此避开原生缩放边框。
6. Rust 用例覆盖右缘、下缘和失焦判定。前端用例确认 WebView 内部失焦不会直接隐藏浮层。

## 4. 验证

- 前端 489 条测试通过。
- TypeScript 检查和 Vite 生产构建通过。
- `cargo fmt --check` 通过。
- 本机缺少 MSVC `link.exe`，所以 Rust 编译和单元测试由 CI 执行。
- 原生托盘交互无法由 jsdom 覆盖。发布后需要在 Windows 上实测缓慢移入浮层、进入边缘和拖拽缩放。

版本从 0.2.8 调整为 0.2.9。
